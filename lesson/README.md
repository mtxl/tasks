# Комплект занятия: вайб-кодинг с OpenCode

Готовые материалы для двух пар по 90 минут на базе учебного проекта
«Таск-трекер» (`server.py`, `data.json`).

**Аудитория:** студенты колледжа, специальность ТРПО, 2–4 курс.
**Подготовка:** базовый Python, HTML и git. Опыт с AI-агентами не нужен.
**Стек:** только стандартная библиотека Python, совместимость с Python 3.8.
**Инструменты:** OpenCode 2.x, браузер, терминал.

## Что внутри

| Файл | Для кого | Зачем |
|---|---|---|
| `plan.md` | преподаватель | Полный сценарий: хронокарта, промпты, ожидаемые ответы, риски |
| `handout.md` | студенты | Раздатка с заданиями, чек-листами и домашкой |
| `materials/AGENTS.md` | студенты | Образец постоянных правил проекта |
| `materials/reviewer.md` | студенты | Образец подагента-ревьюера без права менять файлы |
| `materials/opencode.json` | преподаватель | Пример разрешений `allow` / `ask` / `deny` |
| `materials/data_dirty.json` | студенты | Данные с дефектами для проверки устойчивости и XSS |
| `solutions/server_step1.py` | преподаватель | Эталон после первой пары: фича есть, защиты ещё нет |
| `solutions/server_final.py` | преподаватель | Эталон после второй пары: экранирование, счётчик, тестируемые функции |
| `solutions/test_server.py` | преподаватель | Эталонные тесты на `unittest` |
| `solutions/sample_review.md` | преподаватель | Пример ответа ревьюера для сверки или офлайн-варианта |

`solutions/` — **не показывать до практики 4**. Студенты должны сначала
получить свой результат и проверить его, а не копировать эталон.

## Быстрый старт

1. Проверьте окружение:

   ```bash
   opencode --version   # нужен 2.x
   python3 --version    # нужен 3.8+
   cd tasks
   python3 server.py
   ```

   Откройте <http://127.0.0.1:8000> — должен появиться список задач.

2. Разложите материалы:

   ```bash
   cp lesson/materials/AGENTS.md ./AGENTS.md
   mkdir -p .opencode/agents
   cp lesson/materials/reviewer.md .opencode/agents/reviewer.md
   ```

   `opencode.json` копируйте только в песочницу для демонстрации
   разрешений: он меняет поведение агента и не нужен для остальных заданий.

3. Распечатайте `handout.md`.

4. Откройте `plan.md` и ведите по хронокарте.

## Логика занятия

**Пара 1 — от задачи до фичи.**

- чат vs агент;
- Plan mode: аудит без изменений;
- Build mode: одна фича по критериям приёмки;
- чтение diff и проверка в браузере;
- `AGENTS.md`: постоянные правила проекта;
- git и рефлексия.

**Пара 2 — качество и безопасность.**

- постановка задачи: контекст, ограничения, критерии, проверка;
- свой подагент `reviewer` с запретом на изменения;
- аудит на XSS и необработанные ошибки;
- исправление экранирования;
- `unittest` для чистых функций;
- разрешения и риски;
- итоги.

## Проверка эталона

```bash
# из корня проекта
cp server.py server.backup.py
cp lesson/solutions/server_final.py server.py
cp lesson/solutions/test_server.py test_server.py
python3 -m unittest test_server.py -v
```

Ожидается: 6 тестов, все проходят.

Проверка страницы:

```bash
python3 server.py
# в другом терминале
curl -s http://127.0.0.1:8000 | grep -o 'Всего: [0-9]*, выполнено: [0-9]*'
```

Ожидается строка вида `Всего: 3, выполнено: 0` (зависит от `data.json`).

Вернуть исходники:

```bash
mv server.backup.py server.py
rm -f test_server.py
```

## Если первая пара не успела

Перед второй парой скопируйте эталон первой пары:

```bash
cp lesson/solutions/server_step1.py server.py
```

В нём уже есть кнопка «✓» и `toggle_task`, но остались учебные дефекты:
нет экранирования, нет обработки ошибок, нет тестов. Именно их ищут
студенты на второй паре.

## Если пар меньше или больше

- **Занятия по 45 минут:** оставьте практику 1, практику 2 и рефлексию;
  безопасность и тесты перенесите на следующее занятие.
- **3 пары:** добавьте отдельную пару на фильтр, поиск или CSV и полноценный
  тест-план. Хорошая третья тема — `unittest` для HTTP-обработчика.
- **Нет сети/токенов:** проведите демонстрацию на своём ноутбуке, раздайте
  `solutions/sample_review.md`, оставьте проверку и обсуждение.

## Важные мелочи

- `server.py` запускается в отдельном терминале: это долгоживущий процесс.
  Не запускайте его внутри TUI OpenCode, иначе терминал будет занят.
- Порт 8000 может быть занят. Тогда временно поменяйте порт в `server.py`
  или остановите старый процесс.
- После экспериментов откат:

  ```bash
  git checkout -- server.py data.json
  ```

- OpenCode 2.x подхватывает изменения `.opencode/agents/*.md` и `AGENTS.md`
  без перезапуска.
- На Windows: `python` вместо `python3`, `copy` вместо `cp`,
  `echo %ERRORLEVEL%` вместо `echo $?`.
