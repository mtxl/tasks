# Раздатка студента

## Занятие: вайб-кодинг с OpenCode

**Что нужно:** ноутбук, проект «Таск-трекер», Python 3.8+, OpenCode 2.x, браузер.
**Как работаем:** в парах, роли «драйвер» и «навигатор», меняемся каждые 8–10 минут.

## Что такое OpenCode

OpenCode — это агентская среда. Вы ставите задачу, а агент сам читает файлы,
предлагает план, вносит изменения и запускает команды. Важно: агент не «знает»
проект, он видит только то, что прочитал, и делает только то, что ему разрешили.

| Режим | Что делает |
|---|---|
| **Plan** | Читает, анализирует, предлагает план. Файлы не меняет. |
| **Build** | Меняет файлы и запускает команды. Здесь нужен контроль. |

---

## Правила безопасной работы

1. Сначала **Plan**, потом **Build**. В Plan агент читает, но не меняет файлы.
2. Одна задача — один файл — один понятный результат.
3. Перед запуском опасной команды читаем, что именно она делает.
4. Сломалось — `Esc`, затем `/undo`. Не «чиним» наугад.
5. Секреты, пароли и персональные данные в промпт не вставляем.
6. Любое «работает» проверяем сами: в браузере, в `data.json`, тестами.

**Главная мысль:** агент — исполнитель. Ответственность за результат — на разработчике.

## Задание 2. Фича «Отметить выполненной» (25 мин)

1. Переключитесь в **Build**.
2. Вставьте промпт:

```text
Задача: добавь в server.py отметку задачи выполненной.
Требования:
- у каждой задачи кнопка «✓», у выполненной — «↺»;
- POST /toggle/{id} переключает поле done;
- выполненная задача зачёркнута и приглушена;
- после переключения — редирект на /;
- не менять формат data.json и существующие /add, /delete;
- только стандартная библиотека, Python 3.8;
- переключение оформи отдельной функцией toggle_task(tasks, tid),
  которая возвращает True, если задача найдена;
- load() и save() должны принимать необязательный path
  (по умолчанию data.json), чтобы тесты не трогали рабочие данные.
Критерии приёмки:
1. новая задача не выполнена;
2. клик по «✓» делает её выполненной, текст зачёркнут;
3. повторный клик возвращает в активные;
4. после перезапуска сервера состояние сохраняется;
5. /add и /delete работают как раньше.
Сначала покажи план изменений, код не пиши.
```

3. Посмотрите план. Если он затрагивает лишнее — попросите сузить.
4. Разрешите изменения и проверьте:

- [ ] страница открывается;
- [ ] новая задача добавляется;
- [ ] клик по «✓» зачёркивает текст;
- [ ] после `F5` состояние сохраняется;
- [ ] повторный клик возвращает в активные;
- [ ] удаление работает;
- [ ] `data.json` остаётся валидным JSON;
- [ ] `done` — это `true`/`false`, а не строка;
- [ ] маршрут `/toggle/{id}` работает через POST;
- [ ] после действия приходит `303` и редирект на `/`;
- [ ] нет новых библиотек;
- [ ] нет синтаксиса Python 3.9+.

**Если агент сделал лишнее:** `Esc`, затем `/undo` или попросите
«только один файл и только эта фича».

## Задание 7. Тесты `unittest` (10 мин)

**Промпт:**

```text
Создай test_server.py на unittest для server.py.
Покрой:
1) toggle_task переключает done и возвращает True;
2) toggle_task для несуществующего id возвращает False;
3) build_tasks_html экранирует <script> и не содержит сырой тег;
4) build_tasks_html помечает выполненную задачу классом done;
5) load() на отсутствующем файле возвращает пустой список задач;
6) load() читает корректный временный файл.
Требования:
- только stdlib, Python 3.8;
- временные файлы через tempfile;
- не запускать HTTP-сервер;
- тесты не должны менять рабочий data.json.
```

Запуск:

```bash
python3 -m unittest test_server.py -v
```

Если тест `load()` на отсутствующем файле падает — это не ошибка теста,
а найденный дефект. Добавьте обработку `OSError` и `JSONDecodeError`, чтобы
тест стал зелёным.

Чек-лист:

- [ ] 6 тестов проходят;
- [ ] тесты не трогают `data.json`;
- [ ] нет сторонних библиотек;
- [ ] нет синтаксиса новее Python 3.8;
- [ ] сервер по-прежнему запускается.
