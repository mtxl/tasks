# Пример ответа ревьюера

Этот файл нужен для сверки после практики 4 или как офлайн-вариант, если
нет сети или токенов. Ответ относится к коду после первой пары
(`solutions/server_step1.py`), где фича уже есть, а защиты ещё нет.

## Краткий вывод

Фича «Отметить выполненной» реализована, но приложение уязвимо к XSS:
название задачи вставляется в HTML без экранирования. Кроме того, сервер
падает на отсутствующем `data.json`, на битом JSON и на нечисловом id
в адресе. Тестов нет.

## Таблица находок

| Файл:строка | Проблема | Почему важно | Как исправить |
|---|---|---|---|
| `server.py:34` | `t["title"]` вставляется в HTML без экранирования | XSS: название `<script>alert(1)</script>` выполнится у пользователя | `html.escape(str(t.get("title", "")))` |
| `server.py:8` | нет обработки `OSError` и `json.JSONDecodeError` | сервер падает трейсбеком, если файла нет или он испорчен | вернуть `{"tasks": []}` и обработать ошибку |
| `server.py:125,133` | `int(...)` на последнем сегменте пути | `/toggle/abc` даёт `ValueError` и 500 вместо 400/404 | проверять id и возвращать 400 |
| `server.py:34-38` | `t["title"]` и `t["id"]` без проверки наличия | старые или неполные данные ломают страницу | `.get()` и пропуск записей без id |
| `server.py:34` | `done` может отсутствовать | у старых записей нет поля — страница падает или ведёт себя непредсказуемо | `t.get("done", False)` |
| проект | нет тестов | любое изменение страшно делать | `unittest` на `toggle_task`, `build_tasks_html`, `load` |
| `server.py:118` | `max(id) + 1` | при конкурентных запросах возможны дубли id | для учебного проекта допустимо; для продукта — отдельная стратегия id |
| `server.py:46-82` | HTML собирается конкатенацией | трудно поддерживать и легко забыть экранирование | вынести шаблон или хотя бы централизовать экранирование |
| `server.py:115-119` | нет ограничения длины названия | можно сохранить строку на мегабайты | ограничить длину на сервере |
| `server.py`, формы | нет CSRF-защиты | в реальном продукте форма может быть отправлена с чужого сайта | для локального учебного проекта допустимо; в продукте — токены |

## Что осталось неизвестным

1. Нужна ли авторизация и разные пользователи?
2. Есть ли ограничение на длину названия задачи?
3. Что делать с дублями id в старых данных: исправлять автоматически
   или показывать ошибку?
